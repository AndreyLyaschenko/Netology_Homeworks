# Задание 4*. Развёртывание RabbitMQ-кластера через Ansible

Playbook устанавливает RabbitMQ на **любое число** Debian/Ubuntu-серверов, заданных в группе `rabbitmq_nodes`, настраивает общий Erlang cookie, объединяет серверы в кластер и создаёт политику `ha-all` для quorum-очередей.

## Требования

- Ansible на управляющей машине, SSH-доступ и `sudo` на целевых серверах.
- У целевых серверов должны работать apt-репозитории с RabbitMQ, поддерживающим quorum queues и параметр `delivery-limit`.
- Узлы должны соединяться между собой по TCP 4369 и 25672 (а клиенты — по 5672; UI — 15672). Открывайте порты только доверенным адресам.
- **Не запускайте этот playbook на существующих узлах с важными данными:** при первом присоединении вторичного узла выполняется `rabbitmqctl reset`, удаляющий локальное состояние RabbitMQ.
- Пример использует установку из настроенных apt-репозиториев; версия пакета зависит от ОС и источника пакетов. Для RabbitMQ 4.1 следует заранее подключить совместимый официальный репозиторий RabbitMQ/Erlang.

## Запуск

1. Замените адреса и пользователя в `inventory.ini` на адреса ваших серверов. Для добавления узлов достаточно дописать строки в группу `rabbitmq_nodes`.
2. Создайте зашифрованный файл с cookie:

   ```bash
   ansible-vault create secrets.yml
   ```

   Содержимое в редакторе:

   ```yaml
   vault_rabbitmq_cookie: 'REPLACE_WITH_ONE_LONG_RANDOM_SHARED_COOKIE'
   ```

3. Запустите из каталога `ansible/`:

   ```bash
   ansible-playbook -i inventory.ini playbook.yml -e @secrets.yml --ask-vault-pass
   ```

4. Проверьте кластер на первой машине:

   ```bash
   sudo rabbitmqctl cluster_status
   sudo rabbitmqctl list_policies
   ```

`secrets.yml` не добавляйте в Git. Для этого предусмотрен `.gitignore`.

## Почему политика ha-all отличается от старых примеров

В RabbitMQ 4.x удалено зеркалирование classic queues через `ha-mode`. Поэтому политика `ha-all` с `delivery-limit: 20` **не реплицирует** сообщения. Для отказоустойчивости создавайте quorum-очереди с нечётным количеством участников (например, 3); репликация обеспечивается Raft. Создание конкретной quorum-очереди — отдельная операция, в этом задании playbook настраивает кластер и политику.

## Ограничения

Playbook рассчитан на **первичное развёртывание** новых серверов. Последовательное исполнение (`serial: 1`) снижает риск одновременного вмешательства в узлы, но не заменяет процедуру безопасного обслуживания production-кластера. Перед использованием в производственной среде настройте TLS, учётные записи, firewall, бэкапы и контролируемые обновления.
